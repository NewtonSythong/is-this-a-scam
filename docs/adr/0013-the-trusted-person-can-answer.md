# The Trusted Person answers from a page, and the Message travels in the fragment

ADR 0007 made handing a Message to a Trusted Person a first-class outcome, but it only sent the question. The Trusted Person received a text quoting the Message and had to compose a reply themselves — which is the part of helping that people actually put off, because "it's a scam" is easy to say and easy to say incompletely. The Checker was left waiting on a message that a busy adult child would answer eventually.

So the text now carries a link to `/asked`, where the Trusted Person reads the Message and answers with one of three buttons — *it's a scam*, *it looks genuine to me*, *I'm not sure either* — plus an optional line in their own words. The answer opens as a pre-written text back to the Checker, so the whole exchange is two taps on their side and no typing. The wording is written for them because it carries the action as well as the opinion: what not to do matters as much to a frightened Checker as what the message turned out to be.

**The Message travels in the URL fragment, not the query string.** A fragment is the one part of a web address that no browser sends to the server, so the page assembles itself entirely on the Trusted Person's device and we never receive, and cannot log, the Message it displays. A query string would have been identical to write and would have quietly written every escalated message into the host's access log — which is exactly the promise ADR 0005 makes, broken by the least interesting line of code in the feature. `/asked` is also marked `noindex`, because every one of these addresses has somebody's message in it.

**The link is offered without an account, an install or a request back to us.** The Trusted Person is being asked for a favour by someone worried; making them sign up first would lose most of them at the first screen.

Two things were considered and rejected. **Sending the Checker's number to the server so the answer could be routed** — rejected, because it turns a feature that stores nothing into one that must hold a phone number; instead the Checker's own name and number are optional, kept on their device, and travel in the same fragment. Without them the page shows the Trusted Person the words and asks them to reply in the thread the text arrived in, which costs one paste. **Defanging the scam's own links in the quoted Message** — rejected, because the Trusted Person is being asked to judge the exact words, and altering them removes the evidence; the page instead renders the Message as plain text, so nothing in it is tappable there, and says so.

The cost is length. The same Message now travels twice in one SMS — once quoted, once inside the link — so the quote was cut from 900 characters to 300 when a link goes with it. The quote gives way rather than the link, because the link is the half that can be answered, and a real scam text is well under 300 characters anyway. A typical escalation is around 370 characters in total.

## What a stranger can do with this page, and what stops them

**Amended 2026-09-07.** `/asked` renders text chosen by whoever built the link, on our domain, to a reader who arrived because they were asked for help. That is a page a scammer can address to a victim as easily as a Checker can address it to their daughter, and the design has to assume they will.

Four limits, each on a different thing the link controls:

- **The reply number must be a New Zealand mobile.** It is the only field that makes the reader's phone do something, and left open it means a stranger's page has one large button that texts a number of the stranger's choosing — a premium-rate charge, and a confirmation that the number is live. Every NZ mobile is `02` plus one digit plus six to eight; premium rate is `0900`, so requiring `02` excludes the range outright rather than by a blocklist somebody has to maintain. The number is also printed beside the button, because the link chose it and the reader did not. A number that fails this leaves the page with no send button at all, falling back to the words and a copy button — the same path as a Checker who never gave their number.
- **Names are cut to 24 characters.** Both go into headings, so they are somewhere a stranger can put words on our domain, and nothing sentence-shaped survives that length. They are deliberately not restricted to an alphabet: macrons, hyphens and apostrophes are in real names, and an app for New Zealanders that mangles a Māori name to feel safer has made the wrong trade. The surrounding wording carries the rest of the defence — whoever is named is cast as the person confused and asking for help, which is not a position authority can be borrowed from.
- **Invisible characters are stripped from everything shown.** Bidirectional overrides and zero-width marks let displayed text differ from the text underneath it, which matters most on the one page asking somebody to judge a hostname character by character. Newlines survive, because in a forwarded message they are sometimes the tell.
- **A provenance line sits above everything the link chose**, saying that the page's contents came out of the link, that we did not write them, and that we cannot say who sent them. Without it the page lends this domain's credibility to a stranger's text, which is the whole reason a scammer would want to use it.

What none of this addresses is that the check endpoint is a public classifier, and so an oracle: a scammer can submit drafts until one comes back `unclear`. Rate limiting (ADR 0011) is a brake on that and not a fix, and it cannot be a fix while the app is free and account-less, which are the two things that make it reachable by the people it is for. That trade is made deliberately and is recorded here rather than left implied.
