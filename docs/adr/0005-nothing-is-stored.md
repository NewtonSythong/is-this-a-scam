# The Message leaves the device, and a Check stores nothing

Running the Artifact Check against Safe Browsing and the Narrative Check against a hosted model both require sending the Message off the phone, and that Message may contain the Checker's name, their bank, or a family member's name. Local redaction before sending was considered and rejected: stripping names and numbers would delete the "Hi Mum, my phone broke" signal the Narrative Check exists to catch, so redaction would be removing the evidence. An on-device-only build was rejected because it forfeits Safe Browsing and the entire active-verification layer. So the Message is sent, and in exchange nothing is retained — no accounts, no history, no Check written to disk or to a log — and that promise is stated on screen in words the Checker can read, not buried in a policy page.

**Revised (2026-09-07).** One exception now exists, and it is an exception the Checker themselves creates: a Message they deliberately choose to report is kept until it has been reviewed. Running a Check still stores nothing whatsoever — no account, no history, no log line, nothing written to disk — and that remains the promise for every message that passes through the app. Reporting is a separate endpoint, requires an explicit consent flag that the endpoint refuses to proceed without, and takes two taps with the message shown back before the second. The wording on the page was changed to match rather than left to imply more than the app now does: "It is not saved — unless you choose to report it, so others can be warned." See ADR 0012 for what is kept and for how long.
