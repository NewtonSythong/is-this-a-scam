# How the benchmark works, and how much to trust it

`docs/benchmark-offline.md` and `docs/benchmark.md` are generated by
`npm run bench` and `npm run bench:full`. This file is written by hand and
explains what those numbers are worth, because a percentage with no method
attached is worse than no percentage at all.

## Why a separate corpus exists

`src/data/scamLibrary.nz.ts` is the regression suite. The engine was developed
against those examples and `scamLibrary.nz.test.ts` asserts their verdicts, so it
passes them by construction. Measuring the engine there would be marking its own
homework.

`bench/corpus.ts` is held out: sixteen messages the engine was not built against,
nothing in `src/` imports it, and no message in it duplicates a library example.
That is the only reason the numbers below are informative at all.

The difference shows up immediately. Every example in the regression library
carries a `.top` or `.xyz` domain; not one message in the held-out corpus does.
A corpus written alongside an engine drifts toward the cases the engine already
handles, and this is what that looks like.

## What is measured

The app has three verdicts and none of them means "safe" (ADR 0001), so this is
not an ordinary binary classification.

- A **scam** is handled correctly if it reaches `scam` or `warning`. `unclear`
  is a miss.
- A **legitimate message** is handled correctly if it returns `unclear`, the
  quietest verdict available. Anything louder is a false alarm.

False alarms are tracked separately and weighted heavily in how the results are
read. An app that shouts at a genuine courier text teaches a frightened person
to ignore it, and a corpus made only of scams cannot see that failure at all.
Five of the eight legitimate messages are `hardNegative`: genuine messages
deliberately wearing a scam's clothes — a real courier's shortened link, a real
bank asking you to confirm a payment, a real family member asking for money.

## Results as of 2026-09-07

| | Offline engine only | Both engines |
| :-- | :-- | :-- |
| Scams raised | 2/8 (25%) | 5/8 (63%) |
| Legitimate left quiet | 8/8 | 8/8 |
| Hard negatives | 5/5 | 5/5 |

The honest headline is that **the deterministic half alone catches a quarter of
scams it has not seen before**, and the language model roughly doubles that. The
offline number matters because ADR 0003 promises a complete answer without a key
or a network, and this is what that promise is actually worth.

## Five reasons to distrust these numbers

1. **The corpus has sixteen messages.** Every percentage here moves by six
   points if one message changes. No confidence interval is quoted because none
   would be meaningful.

2. **Only two messages are verbatim.** New Zealand banks and agencies publish
   annotated *screenshots* of scams, not text, so almost nothing can be quoted
   exactly. One of those two is caught. A catch rate over n=2 is not a catch
   rate.

3. **The rest were written by a language model, and half the system under test
   is a language model.** Prose written by Claude may be more legible to Claude
   than a real scammer's would be. This biases the scam-side results *upward*
   and cannot be corrected for here — only disclosed. The verbatim tier is the
   only part free of it, and it is the smallest.

4. **The corpus and a code fix were authored in the same sitting.** The first
   run flagged a genuine NZ Post message as a scam, because `nzp.st` — NZ Post's
   own shortener, named as such on their scams page — was missing from their
   record. That was fixed and the score went up. The fix is justified by NZ
   Post's documentation rather than by the score, but this is exactly the
   mechanism by which a benchmark stops being independent, and a reader should
   know it happened.

5. **Nothing here measures whether the advice helps.** It measures which of
   three words the app picks. Whether a frightened 74-year-old reads the result
   and does something safer is the question that actually matters, and no number
   in this repository addresses it.

## What is still missed

Three scams get through with both engines running:

- `nzpost-warehouse-verbatim` — a real campaign, quoted exactly, with no link
  and no organisation named. There is nothing for the deterministic rules to
  see, and the narrative is bland enough that the model lets it pass.
- `bnz-rewards-expiry` — the payload is the *reply*, not a link. Nothing in the
  message is false on its face.
- `bank-dispute-payment` — a fictitious charge and a "dispute this" link, naming
  no bank at all, so there is no impersonation to detect.

All three share a shape: **no link worth checking, and no organisation named.**
That is the gap, and it is a more useful thing to know than the percentage.

## The corpus is now spent, and that is the most important thing on this page

**Added 2026-09-07.** Three narrative patterns were written to catch the three scams this corpus had shown getting through — `delivery-blocked-pretext`, `benefit-expiry-pretext` and `unauthorised-payment-pretext`. All three misses now pass, and the run reports 16/16.

**Do not read that as the engine having improved by a measurable amount.** The three items were studied in order to write the patterns, so they pass by construction, exactly as every example in `src/data/scamLibrary.nz.ts` does. They are flagged `developedAgainst` in `bench/corpus.ts`, the report counts them separately, and it says they prove nothing.

The subtler problem is with what is left. The report's headline — scams raised among items never developed against — reads 5/5, and that figure carries no information either, because the set of items never developed against is now *exactly* the set that was already passing. Partitioning a corpus by which items you then fixed guarantees the remainder looks perfect. Both numbers on that table are now artefacts of the split.

So the honest position after this change is:

- The corpus gave one clean reading, on 2026-09-07, before any of this: **5/8 unfamiliar scams raised, 0 false alarms, 8/8 legitimate messages left quiet.** That reading stands and is the last one this corpus can give.
- Whether the three new patterns generalise beyond the three messages that prompted them is **unknown and not currently knowable.** Only messages nobody has looked at can answer it.
- The one part still worth something is the legitimate half. It was not tuned *toward* — but each new pattern carries an explicit clause excluding the hard negative nearest to it, and those clauses were written while looking at those negatives. Treat 8/8 as "the fixes were built not to break these", which is weaker than "the fixes do not cause false alarms".

The corpus therefore needs replacing, not extending, before the next engine change is measured — and that is the argument for [`CONTRIBUTING.md`](../CONTRIBUTING.md) putting a real scam text with a citation above every other kind of contribution.
